# data/ 数据台账

> 规则（ai-tool-project-sprint 阶段 1）：每份数据登记来源与许可；规范条目挂出处 + status（`verified`/`pending`）；程序化自制带真值数据是核心资产（固定输入可复现）。`_private/` 目录不入仓。
> 纪律：**未挂原文核对不得落库/生效/进入核查路径**；搜索摘要一律不采信，限值以官方原文/标准元数据直连核对。

### 二·一 条款号纪律（**M1 落地**）

M1 通过 openstd **全文公开系统的在线预览通道**（页图精灵图直连还原，见 §三）取得三份现行标准全文，
逐条核到条款号并写入规则包；`clause` 与 `clause_status` 从此**按条目分别跟踪**（决策 `D-04`/`D-05`）：

- 规则能否进入核查路径由 **`status`（数值已核对）** 决定；
- 条款号能否采信由 **`clause_status`** 单独跟踪：核到即 `verified` 并填 `clause`，**核不到一律 `pending` + `clause: null`**；
- **绝不编造条款号**（编造标准内容比缺失更严重）；
- 两者状态**都在产物中显式可见**，不存在"悄悄当作已核对"。

M1 实测：**11 条条款号 `verified`、6 条 `pending`**（后者为 GB 17761—2018 的 2 条历史对照条目 +
GB 43854/42296 的 4 条首期不参数化条目）。

## 四、合成数据纪律

- **假企业与假车型白名单**：合成企业统一使用虚构名称（如"示例车业（合成）有限公司"）＋虚构统一社会信用代码（测试号段 `90000000…SYN`）；合成车型使用虚构型号（如 `SYN-EB-001`）与虚构技术参数。**不得使用任何真实企业名称、真实车型型号或真实产品参数。**
- **植入真值**：合成车型档案由 `tools/gen_synthetic.py` 生成时同时产出**期望逐项核查结论**（各参数是否越限、整体结论），真值随档案入库；引擎以独立实现路径对账。
- **算例覆盖**：含**限值边界档案**（车速、塑料占比、铅蓄电池车型整车质量各取"恰好等于/低一个计量单位/高一个计量单位"）、**版本差异档案**（同一车型按 2018/2024 两版判定结果不同）、**字段变体档案**（列名"最高车速"/"最高设计车速"/"设计车速"映射到同一标准参数）、**缺参数档案**（未提供塑料占比 → 判 `未提供`，**不得判符合**）。
- **参数集随规则包增长**：M1 新增标称电压、额定功率等参数后，"干净档案"用例由生成器**按规则包实时推导**合规取值补齐（不硬编码），避免用例随规则库过期。
- **误报对照集**：真值库显式声明"应零命中"的干净档案（全参数达标）与"应降级"的档案（质量单位 g/kg 可显式换算 → 只报 `warning`），基准层只读该声明，不自行挑选对照档案。
- 生成器为**唯一写入者**：产物禁手改；再生成须逐字节一致（守门测试）。
