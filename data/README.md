# data/ 数据台账

> 规则（ai-tool-project-sprint 阶段 1）：每份数据登记来源与许可；规范条目挂出处 + status（`verified`/`pending`）；程序化自制带真值数据是核心资产（固定输入可复现）。`_private/` 目录不入仓。
> 纪律：**未挂原文核对不得落库/生效/进入核查路径**；搜索摘要一律不采信，限值以官方原文/标准元数据直连核对。

## 三、数据源可获取性记录（当场验证）

| 数据源 | 预期用途 | 实测结果 | 结论 |
|---|---|---|---|
| openstd.samr.gov.cn 标准检索页（GB 17761 / 43854 / 42296） | 标准编号/日期/状态底座 | ✅ **HTTP 200，可解析的结构化列表**（标准号、名称、发布日期、实施日期、状态、类别） | ✅ 已获取，**可作元数据底座** |
| gov.cn GB 17761—2024 官方问答页 | 关键限值底座 | ✅ **HTTP 200，6,282 字符可读正文**；含车速/整车质量/塑料占比/过渡期等原文数值 | ✅ 已获取，**可作限值底座（覆盖问答所列项）** |
| 标准全文正文（限值条款完整数值） | 完整限值表底座 | ⚠️ **未确认**：openstd 依赖"查看详细/在线预览"（JS），本次未取得可直接解析的全文载荷 | ⚠️ **降级**：规则包入库时逐条挂条款号 + "以正式标准文本复核"为入库前置；**问答未列明的参数（如标称电压 48 V / 额定功率 400 W）一律标 `待核对`，不得凭记忆填数** |
| GB 12268—2025 详情节（用于验证 openstd 详情节可解析性） | 参照验证 | ✅ `newGbInfo?hcno=...` **HTTP 200，4,412 字符**（说明 openstd 详情页本身可解析，但该页亦为 JS 增强） | ✅ 通道可用 |

> **诚实登记**：本题的数据底座由**两个可直连来源**（openstd 元数据页 + gov.cn 官方问答页）支撑；**尚未取得强制标准全文的直接可解析载荷**。因此首期规则包的限值**必须逐条挂条款号并在 M1 入库时以正式标准文本复核**，问答未覆盖的数值项标 `待核对`，不得进入核查路径。

## 四、合成数据纪律

- **假企业与假车型白名单**：合成企业统一使用虚构名称（如"示例车业（合成）有限公司"）＋虚构统一社会信用代码（测试号段 `90000000…SYN`）；合成车型使用虚构型号（如 `SYN-EB-001`）与虚构技术参数。**不得使用任何真实企业名称、真实车型型号或真实产品参数。**
- **植入真值**：合成车型档案由 `tools/gen_synthetic.py` 生成时同时产出**期望逐项核查结论**（各参数是否越限、整体结论），真值随档案入库；引擎以独立实现路径对账。
- **算例覆盖**：含**限值边界档案**（车速 25.0 / 25.1 km/h、塑料占比 5.5% / 5.6%、铅蓄电池车型整车质量 62 / 63 / 64 kg）、**版本差异档案**（同一车型按 2018/2024 两版判定结果不同）、**字段变体档案**（列名"最高车速"/"最高设计车速"/"设计车速"映射到同一标准参数）、**缺参数档案**（未提供塑料占比 → 判 `未提供`，**不得判符合**）。
- **误报对照集**：真值库显式声明"应零命中"的干净档案（全参数达标）与"应降级"的档案（质量单位 g/kg 可显式换算 → 只报 `warning`），基准层只读该声明，不自行挑选对照档案。
- 生成器为**唯一写入者**：产物禁手改；再生成须逐字节一致（守门测试）。
