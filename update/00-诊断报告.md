## 三、做得好的部分（迭代中不要破坏）

1. **双状态门控**：`status`（数值）与 `clause_status`（条款号）独立；`pending` 条目 `value` 必须为 `null` 且不进核查路径；「编造条款号比缺失更严重」写进纪律。
2. **三态判定语义**：`compliant` / `non_compliant` / `not_provided`（未提供）；「未提供」**不改退出码**，与「检出违规」严格分开。
3. **零字面量门禁**（含 docstring/注释扫描 + selftest 正负对照 + token 集非空断言）。
4. **四生成器 + 逐字节冻结守门**：rulesets / synthetic / mapping / knowledge 各有 `--check`，且 `tests/test_gates.py` 覆盖 mapping 与 knowledge 的再生成一致与覆盖性。
5. **规则驱动基准**：`boundary` / `rule_driven` / `dimensions` / `mapping` 四套件不读真值库，从规则表推导，新增规则自动进枚举。
6. **报告确定性**：MD 与自写最小 OOXML XLSX 消费同一 9 章节载荷；`--generated-at` 输入侧时间；两次导出 sha256 相同（我们独立复现）。
7. **发布附件可复现**：`ZIP_STORED` + 条目排序 + 固定 `date_time`，两次打包逐字节一致（留档有 `deterministic: True`）。
8. **发布物冻结态自检**：`frozen=True` + `data_dir within exe dir` 断言；实测通过。
9. **诚实留档**：CI 首跑失败原因（dev extras 缺 Pillow）、48bbe6f 因文档逐字写上游邮箱被 CI 拦下、敏感回显 run 已删等，全部如实记录在 `plan/HANDOFF-M6.md`。
10. **合成数据纪律**：虚构企业名 + 测试号段 `90000000…SYN`、车型代号 `SYN-…`；`.gitignore` 忽略 `data/**/_private/`。
11. **测试规模与说明一致**：全 extras 226、缺 gui 225+1 skipped，README/技术报告/HANDOFF 三处口径自洽。
12. **双 exe onedir + 数据随包**：`_internal/data` 与仓库逐文件同源；CLI 与 GUI 共用 spec 与入口脚本。

## 四、缺陷清单

### D1（P1）README 全部命令都是占位符，仓内没有任何可直接运行的车型档案 —— 「按 README 逐字跑通」在新 clone 上做不到

**现象（实测）**
- `README.md:67-72` 的可用命令全部是 `ebikecheck check <车型.json>` / `scan <目录>` / `compare <上轮目录> <本轮目录>` / `diff-profile <车型.json>` / `export <车型.json> --out-dir <目录>`；`docs/技术报告.md:144` 同样是 `export <档案.json> --out-dir <目录> --generated-at <输入侧时间>`。
- 仓库 tracked 文件里**没有任何** profile 形态的 JSON：`git ls-files | grep -iE "sample|example|profile"` 只命中 `src/ebikecheck/profile.py`、`tests/test_profile_and_paths.py`、`tools/gen_demo_assets.py`。
- **把真值库用例直接当输入会失败**：`py -3.12 -m ebikecheck check data/truth/cases/SYN-CASE-001.json` → **exit 2**，`错误: 档案缺少 profile_id（string）`——因为用例把档案包在 `profile` 键下（`{case_id, kind, target_param, profile, expect, notes}`）。
- 把 `profile` 取出存成独立文件后才可用：`check` rc 0、`export` rc 0（本诊断就是这么做的，文件写在 `%TEMP%`）。
- 而 `README.md:9` 与 `plan/HANDOFF-M6.md:31-38` 都声称「干净环境（`git archive` 树 + 全新 venv）按 README 逐字跑通」「CLI 全子命令实跑通过」。**这个跑通用的档案来自未入仓的 `.tmp/case1-profile.json`**（`.tmp/` 已在 `.gitignore:24` 忽略；本机 `.tmp` 现为 226 MB）。

**影响**
- 陌生人按 README 走到第 2 条命令就无路可走（要么自己造档案、要么读源码猜 `profile` schema）。
- 「README 逐字可跑」是发布类仓库的核心承诺之一，此处断点在文档与仓库资产的接缝上，测试与 CI 都覆盖不到。

**修复方向（见决策 D-2）**
- A（推荐）：入仓 `examples/sample-profile.json`（内容可直接取 `data/truth/cases/SYN-CASE-001.json` 的 `profile` 对象，属合成档案，无真实信息），并把 README/技术报告的命令全部改成这条真实路径。
- B：不改仓库资产，只在 README 补一段「如何从 `data/truth/cases/*.json` 提取 `profile` 生成可用档案」的 `python -c` 一行命令。
- 两种都要在 `tests`（或 `test_gates.py`）加一条"README 里出现的命令路径必须存在"的接线断言，防再次漂移。

### D2（P1）CI 不做历史/提交信息脱敏扫描（只跑 selftest），仓库已转公开

**现象（实测 + 源码直读）**
- `.github/workflows/ci.yml` 的 step 列表：`pytest` / `check_zero_literals` / `check_zero_literals --selftest` / `gen_rulesets --check` / `gen_synthetic --check` / `audit_desensitize --selftest` / CLI smoke（`selfcheck`、`bench`）。
- `grep -rn "--mode" .github/workflows/ci.yml tests/*.py` 只命中 `tests/test_gates.py:269` 的 `--mode tracked`。
- `tools/audit_desensitize.py` 明确支持 `tracked / history / messages / all` 四选一（`--help` 已确认）。
- **手工实测**：`py -3.12 tools/audit_desensitize.py --mode all` → `DESSENSITIZE_AUDIT_OK`，0 HARD；`--mode messages` → 0 HARD/0 REVIEW/0 advisory。
- 即：**工具在、能力在、当前状态干净，但没有任何 CI 步骤在后续提交里复跑 history/messages**。

**影响**
- 已公开仓库的"历史不可撤回"风险没有常驻门禁；一次不慎的提交信息/历史内容泄露不会被 CI 拦住。M6 阶段是手工跑的（`plan/HANDOFF-M6.md` §1.1），之后无自动复跑。
- 同系列其他仓库把 `--mode all`（或至少 history+messages）接线进 CI，本仓库明显弱一档。

**修复方向（见决策 D-1）**：CI 增加 `python tools/audit_desensitize.py --mode all`（保留 `fetch-depth: 0`，`--selftest` 可保留）；并在 `tests/test_gates.py` 加"CI 必须跑 `--mode all`"的接线断言。

### D4（P2）Python 3.8 已 EOL；依赖上界口径不齐（gui 无上界、pyinstaller 无上界）

**现象**
- `pyproject.toml:10` `requires-python = ">=3.8"`；classifiers 列 3.8/3.12；`.github/workflows/ci.yml` 含 `windows-latest / 3.8`；README 第 54 行「要求 Python 3.8+」。
- `gui = ["PySide6>=6.5,<6.7; python_version < '3.9'", "PySide6>=6.5; python_version >= '3.9'"]`——≥3.9 无上界。
- `build = ["pyinstaller>=6", "setuptools<81"]`——无上界（本机 py3.12 装 6.22.3）。
- **实测**：py3.12 + PySide6 **6.12.0** → `226 passed`；Python 3.8 安全支持止于 **2024-10-07**（3.11 至 2027-10-31；3.12 至 2028-10-31）。
- **未验证**：PyInstaller 6.22.3 在 Python **3.8** 上是否可用（PyPI 声明 `>=3.8,<3.16`，但本次只在 3.12 实测构建）。

**修复方向（见决策 D-3）**：抬 `requires-python`（推荐 3.12）；CI 去 3.8 作业；`gui = PySide6>=6.12,<7`；`pkg` 类 extra 加 `<7` 上界并与 README 打包段对齐。

## 八、结论

**建议迭代。** 产品面健康：226 项测试双解释器全绿、八套件基准全达标且门槛来自 manifest、双状态门控与 pending 不生效纪律落实到位、报告两格式两次导出逐字节一致且无外链、发布 zip 与 Release digest 逐位一致、冻结 exe 自检 `frozen=True` 且 bench 达标。
要动的是两件事（都属"接缝处"而非核心逻辑）：
1. **README 的每条命令都指向一个仓内不存在的 `<车型.json>`**：新 clone 无法按 README 跑通 `check/scan/compare/diff-profile/export`（喂真值库用例会 exit 2）；而"干净环境按 README 逐字跑通"用的是未入仓的 `.tmp` 档案。
2. **CI 不跑脱敏的历史/提交信息扫描**（只跑 `--selftest`），且**发布产物本体扫描工具不在仓内**（在 `.tmp/`）——仓库已公开，这两条是"公开后不可撤回"风险的常驻门禁缺口。
另有 P2/P3：演示素材未被 README 展示、无徽章、Python 3.8 EOL 与依赖上界不齐、bench 耗时数字过时、发布包含 `knowledge/raw`（口径与姊妹仓不同，需明确选择）。

**不要**在本轮改规则包数值/status、改三态判定语义、改门槛与 manifest 阈值、改真值库、改退出码语义、改报告九章节结构。
