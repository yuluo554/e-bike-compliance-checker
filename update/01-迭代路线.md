## 五、方法论提醒（这个仓库特有的坑）

- **`check` 只认顶层 `profile_id`**：`data/truth/cases/*.json` 是**用例**（`{case_id, kind, target_param, profile, expect, notes}`），把整个用例文件喂 `check` 会 `exit 2`「档案缺少 profile_id」；示例档案必须是**取出的 `profile` 对象本身**。
- **示例件必须是干净件**：README 的示例命令若 `check` 出 exit 1，陌生人会以为工具坏了；也建议示例 `scan examples` 输出「符合」。
- **`.tmp/` 是被忽略的目录**：验证期草稿放这里（`plan/06` 有约定），因此**任何跑通证据所依赖的输入都不能只存在于 `.tmp/`**——这正是 D1 的根因。改 README 时把输入搬进 `examples/`。
- **脱敏审计器有三模式（tracked/history/messages）没有 dist 模式**：产物本体扫描历史上由 `.tmp/scan_build_artifacts.py` 做；入仓时**豁免清单必须片段拼接**（该仓库曾因在文档里逐字写上游邮箱被 CI 判 HARD，见 HANDOFF-M6 §1.3）。
- **CI 必须带全量历史**：新增 `--mode all` 后仍要 `fetch-depth: 0`（浅克隆会让 history 扫描静默空跑）。
- **`data/knowledge/raw/` 会随包**：`tools/ebikecheck.spec` 的 `datas` 是整棵 `data/`；若 D-4 选"对齐姊妹仓排除 raw"，要同时改 spec 与产物扫描白名单，并重跑冻结态自检。
- **冻结产物无时间戳**：生成器禁时间戳（有守门测试）；改生成器后必须整目录重生成，不要手改 JSON。
- **路径用 `PYTHONPATH=src`**：`python -m ebikecheck ...` 需要 `PYTHONPATH=src`（或 `pip install -e .` 后用 `ebikecheck`）。
- **干净环境**：用 `$TEMP/eb-v011` 新 venv，不复用全局 py3.8/3.12；用完删除并确认 `git status` 只多 `update/`。
