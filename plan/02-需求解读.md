**本文用途**：把题目的"痛点叙事"转成**可验收的功能条目**，并把"不做什么"钉死，防止 scope 失控。

## 一、解读口径（三条，写在最前面）

1. **数值结论只来自规则包**。任何限值、条款号、生效日期都从 `data/rules/` 读取；源码里出现这些数值即为缺陷（由零字面量门禁 FR-17 机器拦截）。
2. **"没查到问题" ≠ "没检查过"**。参数缺失一律判 `not_provided`（未提供/不可判定），**绝不判 `compliant`**；规则未核对一律不进核查路径。
3. **本工具不替代检测机构**。输出是"基于公开标准限值的检查发现"，不是合格判定、检测结论或行政认定（见 §五 边界守卫）。

|---|---|---|---|---|

| P4 | **列名千差万别**（"最高车速"/"最高设计车速"/"设计车速"） | **字段映射引擎**：列名变体 → 标准参数名；不确定即标 `未提供`，绝不臆测 | FR-08 | 映射准确率基准；歧义列名档案必须产出 `未提供` 而非猜测值 |

| P8 | **商业敏感**：车型参数与供应链信息不能外发 | 全本地、零联网、零上传；演示与基准一律合成车型 | NFR-01 / §五 | 运行期无任何外发调用（源码静态核查 + 无 HTTP 依赖） |

### 反面对照：为什么不能用 LLM 聊天替代

| 需求 | LLM 聊天 | 本工具 |
|---|---|---|
| 持久限值规则库（带条款号与 status） | ❌ 每次答可能不同，无法审计 | ✅ `data/rules/` 冻结产物 + sha256 + 逐字节可复现 |
| 参数 × 限值的**确定性**矩阵 | ❌ 概率输出，"大概符合"不可交付 | ✅ 纯函数判定，同输入同输出 |
| 整批清单对账 + 跨轮比对 | ❌ 上下文装不下，且无集合语义 | ✅ 批量扫描 + 三集合对账 |
| 证据指纹（防篡改） | ❌ 无产物 | ✅ 档案/报告双 sha256 |

> 因此本项目 **不使用 LLM**（决策见 [06-决策记录.md](06-决策记录.md)）：领域为纯确定性规则 + 结构化输入，无"非结构化解析兜底"需求。全链路零 API 依赖 → 基准可离线跑、结论 100% 可复现、脱敏面无外部调用。

|---|---|---|---|---|

| **FR-02** | **status 门控**（按作用域） | P0 | M0 | `pending` 条目**零参与**核查；门控计数出现在 `selfcheck` 与报告"未启用"节 |

| **FR-04** | 蓄电池专项核查（GB 43854—2024） | P0 | M2 | 分册规则独立加载、跨标准统一结论、各挂自身条款号 |

## 四、NFR 非功能需求

| NFR | 要求 | 验证方式 |
|---|---|---|
| **NFR-01** | 全本地处理、零上传、默认不联网 | 核心层零 HTTP 依赖（源码静态核查）；文档显式声明 |
| **NFR-02** | 核心层（规则/引擎/基准）**零第三方依赖** | CI 用 core-only 装法跑守门测试（`-e ".[dev]"`，dev 不含重件） |
| **NFR-03** | Python 3.8 兼容（底线） | 本地 3.8/3.12 双跑 + CI 矩阵 |
| **NFR-04** | 确定性：同输入 → 同输出；落盘产物**逐字节可复现** | 生成器"再生成位级一致"守门；报告两次导出 sha256 相同 |
| **NFR-05** | 退出码三语义：0 通过 / 1 检出不符合或未达标 / 2 用法或输入错误 | 锁进 CLI 与 bench 测试 |
| **NFR-06** | 单次全量 bench < 1 秒 | 里程碑收尾必跑项，时长上限随 manifest 下发 |
| **NFR-07** | 平台：Windows 主开发/交付；CI = windows×{3.8,3.12} + ubuntu×3.12 | CI workflow + 首跑对账 |
| **NFR-08** | 非 ASCII 输出在窄编码管道不崩 | `_ensure_utf8_stdio()` 按编码探针 reconfigure；`TextIOWrapper(encoding="cp1252")` 复现测试 |
| **NFR-09** | 可核证性：报告自带"参数来源块"（发布机关/文号/条款/URL/抓取日期） | 报告章节断言 + 无外链硬断言 |
| **NFR-10** | 溯源完整性：明细行数 == 溯源行数，引用 id 全可解析 | 导出前断言，不满足即拒导 |

## 五、边界守卫（非目标 / 纪律，违反即算缺陷）

### 5.1 不做的（来自 01 文 §六，逐条进入测试或文档断言）

| 不做 | 为什么 | 守卫方式 |
|---|---|---|
| 实物检测/试验替代 | 不替代检测机构 | README 免责声明 + 报告固定段 |
| 产品认证受理 / CCC 发证判定 | 非本工具职权 | 同上；`ccc` 相关公告只作**依据登记**，不产出认证结论 |
| 道路通行 / 上牌 / 交管规则判定 | 不同问题域 | 非目标清单 |
| BMS 软件分析 | 超出参数化范围 | 非目标清单 |
| 对接监管申报接口 | 违反零上传红线 | NFR-01 |
| 纯试验方法条款（阻燃、EMC 等）判定 | 无参数化输入面 → 硬判必错 | 规则包中**不建条目**；文档显式写"未覆盖" |
| 真实企业车型参数入库 | 数据纪律 | 合成数据白名单 + 脱敏审计 |

### 5.2 四态判定语义（**最容易被攻击的假合规点**）

| 状态 | 含义 | 触发条件 | 是否算"检出问题" |
|---|---|---|---|
| `compliant` | 符合 | 参数已提供且满足限值 | 否 |
| `non_compliant` | 不符合 | 参数已提供且越限 | **是** → 退出码 1 |
| `not_applicable` | 不适用 | `applies_if` 门控条件不满足（如非铅蓄电池车型不适用 63 kg 条） | 否 |
| `not_provided` | 未提供（不可判定） | 参数缺失 / 单位不可解析 / 映射不确定 | **否，但必须显式列出**，且**绝不折算为符合** |

> **硬约束**：`not_provided` 与 `not_applicable` 都**不是**"通过"。产物中必须与 `compliant` 分列统计；若一条规则都不适用 → 该车型整体记 `not_assessed`（未评估），**不得输出 `compliant`**。

### 5.3 门控纪律（FR-02）

- 规则条目 `status ∈ {verified, pending}`。
- **`pending` 条目不进入任何核查路径**：引擎加载时按作用域过滤，被过滤条目记入 `excluded` 集合。
- 报告与 `selfcheck` **显式写出**"本次核查未启用 N 条（规则待核对）"并列出 id —— **不留空**（"没查"与"查了没问题"是两种结论）。
- 第三方态 `input_required`（本不由规则包承载的外部输入）在 M3 引入（批量扫描的运行期外部输入）；M0 不预置。

### 5.4 数据与合成纪律

- 演示与基准**一律使用合成车型档案**；合成企业用虚构名称 + 测试号段（统一社会信用代码 `90000000…SYN`）、车型代号 `SYN-…`。
- 生成器是**唯一写入者**，产物禁手改；再生成须逐字节一致。
- 证据样本只留结构说明，不入真实文件。

### 5.5 品牌隔离

不复制姊妹项目代码；公开文档不提其余项目业务领域（已按此纪律掩码，见 [06-决策记录.md](06-决策记录.md)）。

## 六、术语与状态语义速查

| 术语 | 定义 |
|---|---|
| 规则包（ruleset） | 一个 `标准 × 版本` 下可参数化条款的结构化集合，JSON，生成器冻结产物 |
| 规则条目（rule） | 最小判定单元：`param + op + value + unit + clause + applies_if + status` |
| 作用域（scope） | 规则包的用途分区；M0 仅 `check`（核查路径） |
| 车型档案（profile） | 输入 JSON：车型标识 + 设计/上市日期 + 参数表 |
| 参数（param） | 标准参数名（规范化后），如 `max_design_speed`；与档案列名解耦（映射引擎负责） |
| 结论（finding） | 一条 (profile × rule) 的判定结果：四态之一 + 条款依据 + 实际值 + 理由 |
| 指纹（fingerprint） | sha256，挂档案与报告 |
| 失败件（failed item） | 批量扫描中无法判定的输入：坏 JSON / 缺字段 / 不可解析；**不是违规** |
| 真值（truth） | 合成车型生成时植入的期望逐项结论；评测以此对账 |
