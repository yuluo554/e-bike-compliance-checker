## 一、数据入库策略

### 1.1 四类数据

| 目录 | 内容 | 来源 | 写入者 | 入库门 |
|---|---|---|---|---|
| `data/rules/` | 限值规则包（3 标准 × 版本 + manifest） | 生成器 + **逐条挂来源核对** | `tools/gen_rulesets.py` | 数值须有可直连来源；无来源即 `pending` + `value:null` |
| `data/mapping/` | 字段映射表 + 单位换算表 | 生成器 | `tools/gen_mapping.py`（M1） | — |
| `data/truth/` | 合成车型档案 + 真值库 | 生成器（自研确定性 RNG） | `tools/gen_synthetic.py`（M1） | 固定 seed |
| `data/knowledge/` | 依据索引 + 官方快照（sha256 登记） | 直连抓取 | 手工 + 快照脚本 | 逐份 sha256 |

### 1.2 数值入库判定树（**核心纪律**）

```
这个数值有可直连的官方来源吗？
├─ 有（gov.cn 问答 / openstd 元数据 / 正式标准文本）
│   ├─ 条款号也能核到？ → status=verified, clause_status=verified
│   └─ 条款号核不到？   → status=verified, clause_status=pending   ← 本项目当前多数条目
│                          （数值可用，条款号显式标"待核对"）
└─ 没有 → status=pending, value=null, clause_status=pending
           （不进入核查路径；禁止凭记忆填数）
```

> **为什么数值可 verified 而条款号 pending**：判定要素是数值，可核证要素是条款号。二者分别跟踪，**都在产物中显式可见**（04 §五）。绝不为了"看起来完整"而编造条款号。

## 二、生成器设计

### 2.1 `tools/gen_rulesets.py`（规则包，唯一写入者）

**输入**：`tools/sources/*.json`（人工维护的**来源登记**：每条含 `param`/`op`/`value`/`unit`/`clause`/`source`/`status`）。

**纪律**：

1. **禁 stdlib `random`、禁 `set` 迭代序、禁系统时钟** → 产物无时间戳，两次运行**逐字节一致**。
2. 输出 JSON：`ensure_ascii=False`、`indent=2`、`sort_keys=False`（保持人工可读顺序）、`\n` 行尾、**UTF-8 无 BOM**。
3. 写盘用 `open(..., "w", encoding="utf-8", newline="\n")`（**不是 `write_text`** —— 3.8 无 `newline` 参数，且默认会把 `\n` 翻成 `\r\n`）。
4. 生成后计算每册 sha256 写入 `manifest.json`。
5. `--check` 模式：重新生成到内存并与磁盘比对，**逐字节不一致即 exit 1**（守门测试调用它）。

**输出**：`data/rules/manifest.json` + `gb17761-2024.json` + `gb17761-2018.json` + `gb43854-2024.json` + `gb42296-2022.json`。

### 2.2 `tools/gen_synthetic.py`（合成车型 + 真值，M1）

**确定性 RNG**：自研 splitmix64（stdlib `random` 不承诺跨版本序列一致）。

**生成物与真值语义**：

```jsonc
// data/truth/cases/<case_id>.json
{
  "case_id": "SYN-CASE-0001",
  "kind": "boundary",              // clean | boundary | version_diff | field_variant | missing_param | unit_convert
  "profile": { ... },              // 车型档案
  "expect": {
    "overall": "consistent",
    "findings": {
      "max_design_speed": "compliant",       // 主期望
      "plastic_mass_ratio": "not_provided"
    }
  },
  "also_expect": { ... },          // 同一构造隐含的其余结论
  "notes": "..."
}
```

**对账语义**（单一实现源 `benchmark/cases.py`，测试与基准共用）：

- 对账按"**档案全部可判定规则的结论集合**"逐项比对，而非只比主期望；
- `expect.findings` ∪ `also_expect` 构成完整期望集；
- **"应零命中"声明**：`kind=clean` 的档案在真值里显式写 `"expect_findings": []`（无越限项），基准断言"检出越限数 == 0"；
- **"应降级"声明**：`kind=unit_convert` 档案写 `"expect_severity_warning": true`。

**算例覆盖**（01 文 §二.5）：

| kind | 构造 | 期望 |
|---|---|---|
| `boundary` | 车速 25.0 / 25.1；塑料占比 5.5 / 5.6；铅蓄电池车型质量 62 / 63 / 64 kg | 恰好等于限值 → `compliant`；超一个最小计量单位 → `non_compliant` |
| `version_diff` | 同档案（铅蓄电池车型 60 kg）按 2024 版 → `compliant`；按 2018 版 → `non_compliant` | 版本切换生效 |
| `field_variant` | 列名"最高车速"/"最高设计车速"/"设计车速" | 映射到同一 `max_design_speed` |
| `missing_param` | 缺塑料占比 | `not_provided`，**绝不 `compliant`** |
| `clean` | 全参数达标 | 越限数 0 |
| `unit_convert` | 质量用 g、车速度用 m/s 等 | 换算后判定 + `severity=warning` |

**确定性守门**：`--check` 再生成逐字节一致；产物无时间戳。

### 2.3 数据生成纪律（生成器通用）

- **唯一写入者**：产物禁手改；改体例走生成器整目录重生成。
- 产物落盘无时间戳；`\n` 行尾。
- 生成器自身**也要过零字面量门禁**（它读 source 文件路径，但不得内联限值数值——数值只能出现在 `tools/sources/*.json`）。

## 三、过渡期与版本口径登记（**动了会打挂基准**）

| 项 | 结论 | 依据 |
|---|---|---|
| GB 17761—2024 实施日 | 2025-09-01 | openstd 元数据 + gov.cn 问答 |
| 生产过渡期 | 至 2025-08-31（此后新生产须符合新标准） | gov.cn 问答 |
| 销售过渡期 | 至 2025-11-30（此后所有销售产品须符合新标准） | gov.cn 问答 |
| **版本锚定主键** | `model_design_date`（次键 `market_date`） | 本设计决策 D-06 |
| **锚定窗口** | `< 2025-09-01` → 2018 版；`>= 2025-09-01` → 2024 版 | 上表 |
| **不混算** | 一次核查只用一个版本；跨版本对照走显式 `--version-of` 或 `version` 基准套件 | 01 文 §二.3 |
| 基准日核验 | 2026-10-14：GB 17761—2024 未见修改单或延期公告，现行有效 | 基准日核验 |

> **口径变更代价**：改动上表任一格 → 版本套件基准 + 边界枚举 + 真值库需整体重生成。故列入"既定口径"，变更须同步改测试与决策记录。

## 六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 条款号无法从公开渠道核到 | 溯源只剩"数值 + 标准号" | `clause_status=pending` 显式标注；报告参数来源块写明"以正式标准文本复核"；**绝不编造** |
| 换版后旧车型误判 | 结论错 | 版本锚定 + 不混算 + 边界枚举基准（M0-8） |
| float 尾差把边界判错 | 误判 | 全链路 Decimal（M0-7） |
| "未提供"被当成"符合" | **假合规**（最危险） | 四态分离 + 单测硬断言（M0-6）+ 报告分列统计 |
| 规则包被手改 | 基准失真 | 生成器唯一写入者 + `--check` 逐字节守门 |
| 打包后数据没随包走 | 换机即废 | 冻结态自检断言数据目录落在 exe 目录内 |
| 零字面量门禁豁免过宽 | 门禁形同虚设 | 豁免口径写死 + `--selftest` 阳性对照 |
