# 10-14-e-bike-compliance-checker 项目计划总览

**项目**：电动自行车合规核查工作台（产品合规工具，Windows 桌面 + CLI 双形态，整车/蓄电池/充电器三维限值矩阵 + 字段映射 + 双版本对照 + 批量车型对账 + 报告导出）
**方法论**：ai-tool-project-sprint（标准条款库 + 版本化限值规则集 + 合成车型档案真值基准 + 证据指纹 + 离线交付）
**项目系列**：同系列第 20 题（前作名称与业务领域按脱敏纪律不入公开仓，见「决策记录」品牌隔离项）
**命名约定**：本地目录 `10-14-e-bike-compliance-checker`（`10-14`=2026-10-14 日期标签）；**GitHub 仓库名 = `e-bike-compliance-checker`（纯净名，去日期前缀）**，沿用系列惯例 `yuluo554/<kebab-name>`；署名 `yuluo554`（LICENSE/pyproject 一致）。
**定位宣言（v1）**：把"这款车型的参数符不符合新国标 → 电池/充电器是否另有强制标准约束 → 整批清单哪几款越限 → 逐项挂标准条款与数值依据"整条链做成**限值表规则化、可批量、留指纹**的本地工作台——LLM 聊天给不了持久限值规则库、参数×限值的确定性矩阵与整批清单的批量对账，本工具是产品合规自查与送检前排查的防线。

**M2 实测摘要（2026-10-14）**：

- **三维判定**：`check` 从"只按整车册判定"推进到**一份档案同时给出整车 + 电池 + 充电器三维结论**（各挂自身标准号与分册，不混册）；统一结论跨三维按"不符合 > 未提供 > 未评估 > 符合"聚合。
- **维度参与度（D-43）**：电池册首期零生效规则、或标准生效日晚于档案锚定日的维度**不参与聚合**，且理由显式记录 —— 避免"无可判项的标准"把整体结论无谓拉成未评估、或拿"尚未生效"的限值判违规。
- **基准扩展**：`boundary` 从 18/18 扩至 **26/26**（覆盖 `<= >= < > == != in not_in range` 与布尔/无量纲条目）；新增 `rule_driven`（26/26，规则驱动端到端）与 `dimensions`（4/4，三维与跨标准聚合）两套件，**均不读真值库**；六套件全绿，耗时 0.063s（上限 1.0s）。
- **单位别名打通（D-44）**：`data/mapping/mapping.json::unit_aliases` 由 `engine/values.py::unit_alias_index` 消费 ——「公里/小时」「公斤」「KM/H」归一后可判定；换算系数仍内置保零依赖，两表由对账测试守门。
- **缺陷修复**：三维化暴露三处真实缺口并修复 —— ①真值"干净档案"用例只补整车册参数（充电器缺失 → 统一结论跌成未提供）；②零生效规则维度混入聚合；③`unit_aliases` 缺 `‰`（与换算表半边脱钩）。
- 测试：**133 项**，Python 3.8.8 与 3.12.10 **双绿**。
